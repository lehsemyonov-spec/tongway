# Tongway — переводчик для Android

## Кто пользователь и как с ним общаться

- Не программист, пишет только с телефона (Android), компьютера нет.
- Общаемся на русском, простым языком, по шагам и без жаргона.
- Перед крупной задачей сначала показать план и дождаться подтверждения.
- Пользователь тестирует на телефоне и описывает проблемы словами и скриншотами.
  Ошибки присылает из экрана «Журнал» (кнопка «Скопировать»).

## Идея

Своё приложение вместо Immersive Translate. Переводит иностранный текст на русский,
в первую очередь с английского. Только Android (на iPhone такое запрещено).
В Google Play не публикуем — ставим `.apk` вручную.

## Этапы

1. ✅ Кружок поверх приложений + перевод текста на экране (ML Kit на телефоне).
1.5. (в работе) Доработка: кнопка в шторке, перевод всего экрана, история, настройки кружка.
   Пользователь решил: **пока только английский**, выбор языка не делаем.
   Распознавание текста на картинках — сделано («жизненно необходимая вещь» для пользователя).
2. Перевод в строке ввода мессенджера: кружок рядом с полем ввода → меню языков →
   набранный текст заменяется переводом (`ACTION_SET_TEXT`).
3. Фотоперевод: камера → распознавание текста → перевод.
4. Перевод документов: PDF, Word, TXT.
5. Выбор облачных переводчиков и нейросетей по ключу API (ключ хранится только на телефоне).
   Перед подключением проверить актуальные условия и доступность из России.

## Решения по первому этапу

- Механика: **перетащить кружок и отпустить** (вариант А). Прицел рисуется над пальцем
  (на 72dp выше центра кружка), текст ищется под прицелом.
- **Захват цели**: перевод только если прицел задержали на месте 0,5 с (дуга заполняется, прицел ярчает,
  вибрация). Быстро перетащил и отпустил — кружок просто переехал, ничего не сканируется.
  Дрожание до 14dp захват не сбрасывает. Так решил пользователь: раньше любое перемещение запускало сканирование.
- Главная задача пользователя — **навести на субтитры в видео** и получить перевод в окошке.
- Переводится **только кусок под прицелом**: самый маленький элемент с текстом в этой точке.
  Если текст длинный, берётся только абзац под прицелом (по координатам символов).
- После отпускания кружок отъезжает к ближайшему краю экрана.
- Убрать кружок — перетащить на крестик внизу. Вернуть — кнопкой в приложении.
- Касание кружка без перетаскивания показывает подсказку.
- Перевод: Google ML Kit Translation на телефоне, **только с английского** (словари других языков
  не докачиваются). Language ID нужен лишь чтобы не переводить русский текст.

## Решения по этапу 1.5

- Касание кружка — меню (подсказка + «Весь экран», «История», «Настройки»).
- Стрелочка (переключатель со стрелкой вверху): на главном экране — «Вы хотите выйти из приложения?»
  (Выйти / Остаться), на остальных — возврат на главный экран (`goHome`).
- «Показать кружок» — объёмная оранжевая кнопка со значком и тенью (`bg_button_main`), «Как это работает» — под ней.
- «Копировать» — кнопка на 1,5 с становится тёмной «Скопировано ✓» + уведомление (`flashCopied`).
- Долгое нажатие на кружок — перевод всего экрана: поверх каждого куска текста тёмная плашка
  с переводом (`ScreenTranslationView`), шрифт ужимается, чтобы влезть. Внизу панель с ходом перевода,
  «Копировать» и «✕». Любое касание экрана закрывает перевод (картинка устаревает при прокрутке).
- Кнопка в шторке — `BubbleTileService`: показать/убрать кружок; если служба выключена — открыть приложение.
  На Android 13+ в настройках есть кнопка «Добавить кнопку в шторку».
- История — `HistoryStore` (JSON в `filesDir/history.json`, до 300 записей), экран `HistoryActivity`:
  поиск, касание — копировать, долгое нажатие — удалить. Сохраняются только переводы кружком-прицелом.
- Настройки — `SettingsActivity`: размер кружка (56/68/82dp), непрозрачность, «отъезжать к краю»,
  сохранять ли историю, вернуть кружок на место. Служба слушает `SharedPreferences` и применяет сразу.

## Оформление (по презентации Verbina, утверждено пользователем)

- Только тёмная тема: чёрный фон, тонкая сетка 32dp, оранжевое свечение по краям (`TechBackgroundDrawable`).
- Акцент `#EA5F0A` (`@color/accent`), сталь для механики. Палитра — `res/values/colors.xml`.
- Шрифты: заголовки Unbounded (вес 340, похож на шрифт слайдов), текст Inter. Лежат в `res/font`,
  обрезаны до латиницы и кириллицы. Лицензии OFL — `docs/licenses`.
- Элементы слайдов: «бургер» + переключатель с оранжевой точкой вверху, кнопки-пилюли,
  тёмные карточки с серой рамкой, номера шагов 01/02/03, точки и номер внизу.
- Пользователь просит футуристичные конструкции: роботы и механическая ДНК.
  Картинки вырезаны из слайдов (`res/drawable-nodpi/*.webp`, края плавно растворяются в фоне).
  Механическая ДНК рисуется кодом (`ui/MechanicalDnaView`), вращается.
- Поверх приложений: кружок — чёрная линза с оранжевым ободком и зубчатым кольцом (крутится во время
  перевода), прицел-HUD с уголками, найденный текст отмечается оранжевыми уголками,
  карточка перевода тёмная с оранжевым свечением, пока идёт перевод — крутится маленькая ДНК.
- Прогресс скачивания словаря: ML Kit сам проценты не даёт, `ModelDownloadWatcher` берёт их из
  системного DownloadManager, а если там пусто — по росту папок приложения (примерно, из ~30 МБ).

## Как устроено

- Всё поверх приложений рисуется окнами `TYPE_ACCESSIBILITY_OVERLAY` из службы
  спец. возможностей. Поэтому отдельное разрешение `SYSTEM_ALERT_WINDOW` не нужно.
- `TranslatorService` — служба спец. возможностей, держит `OverlayController`.
- `ScreenTextFinder` — ищет текст в точке через дерево `AccessibilityNodeInfo`.
- `TranslationEngine` — ML Kit (определение языка + перевод), общий на всё приложение (`App.engine`).
- `AppLog` — журнал в файле `filesDir/log.txt`, экран `LogActivity`.
- Android 13+ блокирует включение спец. возможностей для приложений из `.apk`, пока в
  «О приложении» → ⋮ не нажать «Разрешить ограниченные настройки». Это объяснено на главном экране.
- Текст на картинках — `ImageTextFinder`: снимок экрана `AccessibilityService.takeScreenshot`
  (Android 11+, `canTakeScreenshot` в конфиге службы, без отдельного разрешения) + ML Kit Text Recognition
  (латиница, модель внутри APK). Кружок на время снимка становится прозрачным (пауза 90 мс).
  Прицел: если в дереве экрана текста нет или это подпись к картинке (`Found.weak`) — ищем абзац на снимке.
  Весь экран: к обычному тексту добавляются куски со снимка, которые не перекрываются с ним больше чем на 50%.
  Приложения с защитой от снимков (банки и т. п.) дают ошибку или чёрный снимок — причина пишется в карточке и журнале.
- Прицел + картинка: распознаётся **только полоса вокруг прицела** (во всю ширину, ±80dp) —
  под субтитры; маленькая анимация-сканер в этой полосе (`ScanOverlayView` с `area`, 0,5 с).
  В карточке кнопки-бонусы «Весь текст» (весь экран одним списком в карточке, в историю одной записью)
  и «Поверх фото» (плашки) — они **заново сканируют весь экран** с большой полосой (1,1 с)
  и подписью «Найдено абзацев: N». Пользователю перевод всей страницы нужен не всегда.
- Режим «следить за субтитрами» (автоперевод каждой новой фразы) — обсуждали, пока не делаем.
- Шторка (кнопка в панели уведомлений) — оставляем как есть. «Прятать кружок у края» — не нужно.
- **Пальцевый перевод**: включается двойным касанием кружка или «Пальцем» в меню (меню из-за этого
  открывается с задержкой 280 мс); режим остаётся включённым, выключается касанием кружка или ✕ на плашке
  вверху. Слой на весь экран (`FingerCanvasView`) ловит палец и рисует светящуюся линию; кружок
  переставляется поверх слоя. Снимок экрана — в момент касания (линия скрыта до готовности снимка),
  чтобы субтитры не сменились. Слова (ML Kit Elements) читаются только в области вокруг линии,
  выбор и порядок чтения — `FingerSelect` (чистый Kotlin, есть тесты: наклон, толщина 10/40/100, обратный
  мазок). Толщина 10–100 (по умолчанию 40) = 0,5 dp за единицу: 40 → 20 dp ≈ строка, 100 → 50 dp ≈ 2 строки.
  **Два и более пальца — не перевод, а жест для приложения** (приблизить/подвинуть фото): линия стирается,
  слой становится `FLAG_NOT_TOUCHABLE`, а движение пальцев повторяется приложению через `dispatchGesture`
  с продолжением штрихов (`GesturePasser`, нужен `canPerformGestures` в конфиге службы). Слой снова ловит
  палец через 80 мс после конца жеста; если реальные касания перестали приходить 4 с — жест отпускается.
  Листать одним пальцем в режиме нельзя (один палец = линия).
- **Архив версий**: каждая сборка — ещё и выпуск «Tongway 0.1.N» (тег v0.1.N), хранятся последние 20.
  Постоянная ссылка: https://github.com/lehsemyonov-spec/tongway/releases (кнопка «Прошлые версии» в настройках).
  Android не ставит старую версию поверх новой — откат делаем новой сборкой со старым кодом.
- Страница со снимка собирается **по строкам** в `PageLayout` (чистый Kotlin, без Android — проверяется
  на компьютере: `kotlinc` из релиза GitHub JetBrains/kotlin, тестовые страницы с наклоном/колонками/мусором):
  наклон страницы = взвешенная медиана углов строк, строки «поворачиваются обратно»; отсев: < 2 букв,
  уверенность распознавания < 0,5 (рукописные пометки), наклон > 12° от страницы (текст боком на полях),
  короткие строки у края кадра, зоны `exclude` (системные панели; для всего экрана — ещё надписи приложения
  из дерева спец. возможностей, например заголовок галереи). Колонки — по перекрытию с последней строкой
  колонки; абзац рвётся на пустой строке, красной строке (отступ) или короткой строке с точкой.
  Мелкий текст (строка < 26 px) распознаётся ещё раз на снимке, увеличенном вдвое.
  На изогнутой странице ML Kit режет строку на куски — `mergeSegments` склеивает куски на одной высоте
  с зазором < 1,5 высоты строки (до деления на колонки; иначе правые половинки строк становились «колонкой»).
  Строка без точки перед красной строкой — заголовок, отдельный абзац.
- Проверка ответа нейросети: `max_tokens` с запасом, `finish_reason = length` → ошибка, перевод короче 45%
  оригинала → «перевела не весь текст» (было: вместо страницы «В ТЕКСТЕ 2. Сателлитные»). Тогда другая модель,
  потом «Весь текст» по абзацам пронумерованными кусками, телефон — в последнюю очередь.
- Умная полоса: если абзац под прицелом касается края полосы — это печатный текст, дочитываем тот же снимок
  целиком и берём абзац полностью. Субтитры остаются быстрыми.
- «Весь текст» уходит в нейросеть **одним документом** (абзацы через пустую строку) — связный перевод.
  Плашки — пронумерованный JSON-объект; пропущенные куски досылаются, телефон — только в крайнем случае.
  Для текста с фото в задание добавлено: «молча исправь явные ошибки распознавания».
  Так исправлены 5 видов ошибок с печатных страниц, которые прислал пользователь (порядок строк при наклоне,
  смесь перевода телефона и нейросети, ошибки букв, мусор с экрана/полей/пометок, слабый перевод телефона).
- Нейросети — порядок задан пользователем (`TranslationEngine.runCloud`): 1) Groq — перебор **всех** его моделей
  по очереди (ручная → прошлая удачная → сильные семейства, `CloudClient.rank`); в статусе и в карточке
  видно «Groq · модель»; 2) если ни одна не ответила — **OpenRouter (до 4 моделей) и второй круг Groq
  параллельно** (`select`), берётся первый ответ, второй останавливается; 3) не вышло — телефон.
  Неверный ключ / нет сети / доступ запрещён — другие модели того же сервиса не пробуем.
  Общий код — `CloudClient` (API, совместимый с OpenAI). У каждого сервиса свой блок в настройках
  (`view_cloud_provider.xml`): ключ, «Вставить», инструкция (`KeyHelpActivity` с EXTRA_PROVIDER), модель,
  «Проверить», счётчик. Mistral/Gemini — возможные следующие звенья (Mistral просит телефон, Gemini — VPN).
- Подробности про OpenRouter: у каждого пользователя (и у друзей) **свой** ключ, вшивать общий
  ключ в APK нельзя. Ключ шифруется ключом Android Keystore (`SecretStore`), в журнал — только маска.
  Настройки → «Переводчик»: «На телефоне» / «Нейросеть», ключ, «Вставить ключ», «Как получить ключ»
  (`KeyHelpActivity`), выбор модели (по умолчанию авто), «Проверить», счётчик запросов за день.
  `OpenRouterClient`: только бесплатные модели (`:free`), автовыбор по семействам (gemini, deepseek, llama…),
  список моделей обновляется раз в сутки. Ответ 429 бывает трёх видов: личный дневной лимит, частые
  запросы, перегрузка бесплатной модели у поставщика (у пользователя так было с gemma-4 уже на 2-м запросе).
  При перегрузке/пропаже модели автоматически пробуются ещё до 2 других бесплатных моделей.
  Лимит бесплатно ~50 запросов/день, 20/мин → **экономим**: абзац = 1 запрос, весь экран / весь текст —
  все куски одним запросом (JSON-массив, куски по ~6000 символов), повторы из памяти (`cloudCache`).
  Если облако не ответило (лимит, нет сети, ошибка) — **молча переводим на телефоне** с пометкой в карточке
  (пользователь выбрал вариант «а»). В карточке и истории видно, кто переводил.

## Сборка

- В облачной сессии Android SDK скачать нельзя (dl.google.com закрыт), поэтому сборку
  проверяем только через GitHub Actions (`.github/workflows/build.yml`).
- Каждая сборка выкладывает `tongway.apk` в пре-релиз `latest`:
  https://github.com/lehsemyonov-spec/tongway/releases/download/latest/tongway.apk
  Запасная ссылка (ветка `apk`, без срока действия ссылки — с телефона качается надёжнее):
  https://raw.githubusercontent.com/lehsemyonov-spec/tongway/apk/tongway.apk
- В APK только `arm64-v8a` и `armeabi-v7a` (без x86), чтобы файл был вдвое меньше.
- `versionCode` = номер сборки GitHub Actions, чтобы новая версия ставилась поверх старой.
- **Печать (ключ подписи)** — секрет репозитория `TONGWAY_KEYSTORE` (base64 файла PKCS12, EC P-256,
  alias `tongway`, пароль `tongway-release` — пароль не секрет, секрет — сам файл). Сборка кладёт его во
  временный файл → `TONGWAY_KEYSTORE_FILE` → `signingConfigs.tongway`. Секрет добавляет пользователь
  (у Claude нет доступа к секретам). Пока секрета нет — подпись старым открытым `app/debug.keystore`
  с предупреждением; после перехода на секрет `debug.keystore` удалить. Смена печати = одна переустановка.
- Собирается **окончательная версия** (`assembleRelease`, без сжатия кода, проверка стиля не останавливает сборку).
- Версии: AGP 8.7.3, Kotlin 2.0.21, Gradle 8.11.1, compileSdk 35, targetSdk 34, minSdk 26.
